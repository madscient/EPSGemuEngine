## 2. 2026-10-02 FmEngineApi の改定への追随

### 2.1 部位ゲイン

- `FmEngine_SetPartGain` / `FmEngine_GetPartGain` / `FmEngine_GetPartMask` を
  エクスポートし、どのチップも部位を持たないとした。`GetPartMask` は `FM_OK` で 0、
  `Set/GetPartGain` は常に `FM_ERR_INVALID_ARG`。未知の `chip_id`・null の出力
  ポインタを `FM_ERR_INVALID_ARG` にするのは YMEngine に揃えた
- 根拠: 仕様書の部位の表に本エンジンのチップは無く、表に無いチップは部位を持たない
  と仕様書にある（**確認済み(読解)**）
- 3 関数は任意のエクスポートで、エクスポートしなくても呼び出し側の扱いは同じ。
  エクスポートした理由: ヘッダ（参照ヘッダの写し）が宣言する関数を DLL も持つように
  するため。仕様が部位ゲインを必須に上げても準拠のままでいられる
- 前提: 仕様書の部位の表に本エンジンのチップが載らないこと。載ったら `Generate` の
  合成を部位ごとに分ける。`Generate` は SSG 部（`chipCalcStereo`）・AMM 部・
  ADPCM 部・PCMD8 を別々の関数で足し込んでいる（**確認済み(読解)**）
- SSGS / SSGS2 の SSG 部と ADPCM 部、SSGS3 の SSG 部と AMM 部が別の端子から出るかは
  データシートで確かめていない（**推測**: SSGS には SSG-ADPCM ミックスレベルの
  レジスタが、SSGS3 には SSG と AMM それぞれのトータルボリューム（`0x32` と `0x01`）が
  あり、チップの中で混ぜていると読める）

### 2.2 外部メモリの種別: `FM_MEM_AMM` を廃止し `FM_MEM_PCM` に統合

- 発端: 仕様書 `e002890` が `FM_MEM_ADPCM_B_ROMMODE = 4` を割り当て、本リポジトリ
  独自の `FM_MEM_AMM = 4` と番号が重なった
- 決定（ユーザー）: AMMS-A / SSGS3 の AMM フレーズ ROM も `FM_MEM_PCM` で受ける。
  分けておく意味が薄いため。SSGS / SSGS2 の ADPCM ボイス ROM と PCMD8 の外部メモリは
  前から `FM_MEM_PCM` だった
- 前提: 1 チップが持つ外部メモリは 1 種類（AMM 部・ADPCM 部・PCMD8 を 2 つ以上持つ
  チップが無い）。`ChipEntry::mem`（割り当ての表）が 1 つなのもこの前提による。
  崩れたら（2 種類のメモリを持つチップを足すとき）種別を分け、番号は仕様書で
  割り当ててもらう
- 影響: `FM_MEM_AMM`（4）を渡す呼び出し側は `FM_ERR_UNAVAILABLE` になる。手元に
  ある互換エンジン・利用側のリポジトリをソース検索した範囲では、`FM_MEM_AMM` を
  使っているのは本リポジトリだけだった（**確認済み**、2026-10-02）
- 見送った案:
  - 仕様書に `FM_MEM_AMM = 5` を登録する。理由: 1 チップ 1 種類なので分ける意味が
    薄い。仕様書（別リポジトリ）の変更も要る
  - 仕様書の `FM_MEM_ADPCM_B_ROMMODE` を 5 に繰り下げ、`FM_MEM_AMM = 4` を登録する。
    理由: DSAemuEngine が `FM_MEM_ADPCM_B_ROMMODE = 4` を実装済みで、波及する
  - 4 をチップごとに読み替える（YMZ770 系なら AMM）。理由: 同じ番号が別のメモリを
    指すことになる

### 2.3 `FmEngine_SetMemoryEx`（任意）は一度見送った

§2.7 で実装した。以下は見送ったときの記録。

- 決定（ユーザー）: 今回は実装しない。`FmEngine_SetMemory` だけでも仕様に準拠する
- 実装するときの論点（**確認済み(読解)**）:
  - PCMD8: `extern/ymz280b` は外部メモリを範囲検査なしの生ポインタ
    （`m_ext_mem[...]`）で直接読み書きする。割り当ての表を通すには、コアを `src/`
    にフォークしてメモリアクセスを関数経由にするか、無改変のまま ROM を `SetMemory`
    と同じ 16MB の複製（§2.6）に写し、RAM は base 0・16MB 以上の 1 ブロックだけ
    受けるかになる
  - AMM 部: `mpeg_audio` は ROM 先頭のポインタを持って読む。ROM は平坦なバッファへの
    複製で表せる。RAM をその場で読むには base 0 の 1 ブロックに限られる
  - SSGS / SSGS2 の ADPCM 部: 読み出しが `ymz_adpcm_device::rom_byte` を通るので、
    割り当ての表に置き換えやすい
- 呼び出し側は `GetProcAddress` で有無を確かめる約束なので、エクスポートしないことで
  壊れる呼び出し側は無い（仕様書の約束による。**確認済み(読解)**）

### 2.4 `FmEngine_GetNativeRate`

仕様書に「FM と SSG を別のレートで生成するチップ (OPN 系) では FM 部のレート」が
加わった。本エンジンのチップは FM 部を持たず OPN 系に当たらないので、変更しない
（SSGS3 は SSG 部のレート、AMMS-A はその時点の AMM の fs を返す。README のとおり）。

**確認済み**（変更前の `63c8834` と変更後を同じ手順（VS 2026 の cl、Ninja、Release）で

入れていない）:

  未知の `chip_id`、null 引数）、AMMS-A / SSGS3 の `FM_MEM_PCM` での `SetMemory` と
  `GetMemorySize`、種別 4 が `FM_ERR_UNAVAILABLE` になること、`SetMemoryEx` が
  エクスポートされていないこと
- 変更前の DLL では同じ検査のうち 7 項目が落ちた（部位ゲインのシンボルが無い、

### 2.6 PCMD8 の `FmEngine_SetMemory` は渡されたデータを書き換えない

- 決定（ユーザー）: `FmEngine_SetMemory` の `data` は `const` なので、エンジンは
  書き込まない。エンジンが複製した場合、複製に何を書いても呼び出し側には戻らないので、
  呼び出し側から見れば書かれないのと同じ。複製を許す以上、複製の使い方（チップの
  書き込みを複製に入れるか）はエンジンの実装による
- 変更前の PCMD8 は、`const_cast` で外したポインタを ymz280b コアに渡していた。
  `0x87` の書き込みが呼び出し側のデータに入り、コアはアドレスの範囲検査もしない
- §2.7 でコアをフォークしたので、複製は渡された大きさだけにし、範囲外は割り当ての
  無い番地として扱うように改めた。以下の 16MB の複製はその前の版
- 対処（ユーザーが選んだ案）: `SetMemory` で、アドレス空間全体（24bit、16MB）の 0 埋め
  バッファへ複製し、コアにはそれを渡す。チップの書き込みは複製に入り、チップから
  読める。データの範囲外は 0 として読め、範囲外アクセスも無くなる。16MB を超える部分は
  使わない。外部メモリを外す（`data` が null または `size` が 0）と複製を解放する
- 前提: PCMD8 1 個あたり 16MB を確保してよいこと
- 見送った案:
  - 渡された大きさだけ複製する。理由: 範囲外アクセスが残る
  - `0x87` の書き込みをエンジンで捨てる。理由: `0x87` はアドレスを 1 つ進める役目も
    兼ね、無改変のコアでは書き込みだけを捨てられない。コアのフォークが要る
- 仕様書の読み方: FMEngineTest `df7dae8` の `docs/FmEngineApi.md`「外部メモリ設定」の
  「`FmEngine_SetMemory` に渡したデータを…チップからの書き込みをデータに反映するかは、
  エンジンのコア実装によります」は、複製したときの複製の使い方の話で、上の決定と
  食い違わない（ユーザーの説明、2026-10-02）。呼び出し側のバッファへの書き込みを
  許す文ではない。その後 `c0589c1` で、仕様書に「エンジンは `data` に書き込まない」と
  明記された（**確認済み(読解)**）

**確認済み**（変更前の `061cece` と変更後を §2.5 と同じ手順でビルドし、検査プログラムを
両方に当てた）:

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 書き込める普通のバッファが `0x87` の書き込みで変わらない | 落ちた（書き換わった） | 通った |
| 読み取り専用のページを渡して `0x87` に書いても落ちない | 落ちた（アクセス違反） | 通った |
| データより先（1MB、未確保の領域）のアドレスを読み書きしても落ちない | 落ちた（アクセス違反） | 通った |
| チップが `0x87` で書いた波形を 8bit PCM で鳴らした出力が、同じ波形を `SetMemory` で渡した出力とビット一致（無音でない） | 通った | 通った |
| 上の書き込みの後も呼び出し側のバッファが変わらない | 落ちた | 通った |
| 外部メモリを外すと `FM_OK`・大きさ 0・無音、付け直すと鳴る | 通った | 通った |
| 16MB を超えるデータを `FM_OK` で受け、大きさをそのまま返す | 通った | 通った |

§2.5 の検査（全 9 チップの出力のダンプを含む）も変更前後で 20 項目すべて通り、ダンプは
ビット一致した。

### 2.7 `FmEngine_SetMemoryEx` を全チップで実装

- 決定（ユーザー）: `SetMemoryEx` は、音源チップが書いた結果をアプリケーションに戻す
  ことを保証するために足されたもの。メモリに書き込む機能を持つチップは実装するべき。
  本エンジンでは PCMD8 が当たる。`FM_MEM_PCM` を持つほかのチップ（SSGS / SSGS2 /
  SSGS3 / AMMS-A）も実装する。エクスポートすると、これらに「持たない種別」として
  `FM_ERR_INVALID_ARG` は返せないため
- 仕様書 `c0589c1` に「外部メモリのバスが外に出ているチップを扱うエンジンは
  エクスポートを勧める」と書かれた。本エンジンの 5 チップはどれも外付けの ROM か
  メモリを持つので、勧められる側に当たる（**確認済み(読解)**）
- PCMD8 に新しいメモリ種別は要らない。コアの再生の読み出し・`0x86` の読み出し・
  `0x87` の書き込みはすべて同じ 24bit の空間を指す（**確認済み(読解)**）。ROM と SRAM が
  同じ空間に並ぶ構成は `base` と `access` で表せる。コアのコメントはデータシート
  LSI-4MZ280B3 を引いて「16MB までの ROM または SRAM を接続できる」と書く。実機に ROM と
  RAM を切り替えるビットが無いことはデータシートで確かめていない（**推測**: MAME の
  コアの作りと、レジスタ表に `0xFF` の MENB しか無いこと）

**実装**

- 割り当ては `src/MemMap.h` の表で、チップごとに 1 つ（§2.2 の前提）。割り当ての無い
  番地は 0 を読み、書き込みは捨てる。ROM のブロックへの書き込みも捨てる
- 引数の扱いは YMEngine `ac29207` に揃えた。未知の `chip_id`・持たない種別・`size` 0・
  `base + size` が 2^32 を越える・既存の割り当てと重なる・未知の `access` は
  `FM_ERR_INVALID_ARG`。`data` が NULL なら重なる割り当てをすべて外す（重なりが無ければ
  何もしない）。`SetMemory` はそれまでの割り当てを置き換える。`GetMemorySize` は
  割り当てたブロックの大きさの合計
- PCMD8: ymz280b コアを `src/Ymz280b.{h,cpp}` にフォークし、外部メモリのアクセス
  9 箇所を関数経由にした。`extern/ymz280b` は無改変のままフォーク元として残し、
  ビルドから外した。`SetMemory` は渡された大きさだけ複製し、書ける割り当てとして持つ
- SSGS / SSGS2 の ADPCM 部: `rom_byte` が割り当ての表を読む
- AMM 部: デコーダは ROM 先頭のポインタと、読み出し上限をビット数の `int` で持つ。
  `base` 0 の 1 ブロックならそのまま渡す（RAM もその場で読める）。それ以外は ROM を
  つないだ複製を渡す。RAM を含む割り当てで複製が要る形になると `FM_ERR_UNAVAILABLE` を
  返し、割り当ては変えない。24bit を超える番地のブロックは読まない。渡す大きさは
  16MB で打ち切る（ビット数が `int` をあふれないため）
- 割り当てを変えると、その部をリセットする（`SetMemory` の従来の挙動に揃えた）
- PCMD8 は、割り当てが空の間はレジスタ書き込みを無視する（従来どおり）。0 が続く
  4bit ADPCM は無音にならないため

**`SetMemory` の利用者から見える挙動の変化**

- AMM 部: ROM の大きさを超える番地を、折り返し（`offset % size`）ではなく 0 として
  読む。仕様の「割り当ての無い番地は 0」に揃えた。移植元の MAME は折り返しに FIXME を
  付けていた。ROM の範囲内で完結するデータでは変わらない（**確認済み(読解)**。§2.5 の
  ダンプも一致）
- PCMD8: 複製は 16MB ではなく渡した大きさになった。渡した大きさを超える番地への
  `0x87` の書き込みは捨てる（§2.6 の版では 16MB の複製に入り、読み返せた）

**見送った案**

- PCMD8 のコアを無改変のまま、ROM を 16MB の平坦な複製で表し、RAM は base 0・16MB 以上の
  1 ブロックだけ受ける。理由: SRAM を空間の一部に置く構成を受けられない
- 毎回の `Generate` の前後で、ブロックと平坦なバッファの間を写し合う。理由: 仕様の
  「その場で読み書きする」に当たらない
- AMM 部の RAM を複製して受ける。理由: 同上
- PCMD8 用のメモリ種別を足す。理由: 上のとおり 1 つの空間で表せる

**確認済み**（変更前の `03db3a8` と変更後を §2.5 と同じ手順でビルドした）:

- `SetMemoryEx` の検査 48 項目が変更後ですべて通った。エクスポート、引数（17 項目）、PCMD8 の
  RAM（チップの書き込みがブロックにその場で入る、呼び出し側の書き込みがチップから
  見える）・ROM（書き込みを捨てる）・割り当ての無い番地・ROM と RAM の同居・
  `SetMemory` による置き換え、ADPCM 部の 1 ブロック・分割・RAM、AMMS-A と SSGS3 の
  AMM 部の 1 ブロック・分割・RAM（その場で読む、`UNAVAILABLE` の 2 通り）。出力を
  比べる項目の基準はどれも無音でない
- 変更前の DLL には `SetMemoryEx` が無く、検査を当てられない。代わりに実装をわざと
  壊した 4 つの版を作り、対応する検査が落ちることを確かめた:

| 壊し方 | 落ちた検査 |
|---|---|
| ROM のブロックも書けるようにする | PCMD8 ROM の 2 項目、AMM の分割 ROM 2 項目（RAM 扱いになり `UNAVAILABLE`） |
| AMM 部が RAM も常に複製する | AMM の RAM の 8 項目（その場で読まない、`UNAVAILABLE` にならない） |
| RAM への書き込み位置をずらす | PCMD8 の RAM・分割・`SetMemory` の複製の 5 項目 |
| `SetMemory` が古い割り当てを残す | `SetMemory` による置き換えの 2 項目 |

- §2.6 の 9 項目、§2.5 の 19 項目（「`SetMemoryEx` をエクスポートしない」の 1 項目は
  今回の変更で逆になった）も通り、全 9 チップのダンプは変更前後でビット一致した
- エクスポートは必須 14 + 部位ゲイン 3 + `SetMemoryEx` の 18 シンボル（`dumpbin /exports`）

**未検証**: Linux / macOS（GCC / Clang）でのビルド、FMEngineTest からの読み込み、
本物の音声データ・AMM フレーズデータでの再生。
